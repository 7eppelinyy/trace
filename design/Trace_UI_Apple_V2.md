# Trace 客户端 UI V2 提案

日期：2026-10-04。范围：方案与实施顺序；尚未修改小程序页面或发布客户端。

## 方向

Apple Stocks 的数据秩序 + Apple Notes 的阅读体验。
用清楚的层级、统一留白、顺畅反馈建立品质感。磨砂材质主要放在导航、工具栏、输入区等浮动控件；阅读和行情内容保持稳定、清晰的表面。

参考：[Apple Materials](https://developer.apple.com/design/human-interface-guidelines/materials)、[Apple Motion](https://developer.apple.com/design/human-interface-guidelines/motion)。以下数值是 Trace 的建议值，并非 Apple 的强制规范。

## 全局基础

- 浅色主背景建议 `#F5F5F7`，内容面 `#FFFFFF`，主文字 `#1D1D1F`，次级文字 `#6E6E73`，操作色 `#007AFF`。
- 页面左右边距 40rpx；采用 8rpx 间距阶梯。正文 30–32rpx，元信息 24–26rpx，大标题 56–64rpx。
- 正文行高约 1.6，标题约 1.3。行情数字使用等宽数字，避免更新时抖动。
- 内容卡片圆角 24–32rpx；同用途控件共用同一套圆角、字号与间距。
- 层级主要由字重、间距和背景建立，阴影只用于真正浮起的控件。
- 红绿保留给行情；上涨/下跌同时显示正负号。事实类别用中性或蓝色标签。
- 单一导航区域协调微信胶囊、安全区和页面标题，避免系统标题与自绘标题重复。
- SF/PingFang 等使用系统字体回退；按 iOS、Android 真机实际显示核对。
- 常用触控区域至少 88rpx 左右，不能用视觉上很小的图标限制命中范围。

## 页面改版

| Before | After | Why |
| --- | --- | --- |
| 首页 Trace 标题 + 技术副标题 + 多个同权重区域 | 大标题“雷达”，小号日期；市场概览、今日重点、事件流形成三级层次 | 先看市场，再看值得关注的事件 |
| 大量事件元信息、传导标签和标的胶囊 | 每条事件突出标题与一句摘要；来源、时间退为小号元信息；标的优先展示两项，其余折叠 | 提高浏览速度，降低视觉噪声 |
| 推演页顶部常驻长问题建议，回答是一整块文字 | 空白态展示短问题建议；进入对话后收起建议；回答分成结论、解释、成立条件和资料来源 | 回答可以阅读、扫描和追问 |
| 推演里“事实穿透”“4级图谱”等固定技术表述 | 按后端实际状态呈现“原文引用 / 条件推断 / 情景假设 / 背景解释”；图谱显示真实层数 | 让界面状态与实际能力一致 |
| 自选页“录入”“清空”等操作常驻 | 标题“自选”；搜索与添加为主要操作，批量管理放进编辑模式；保留左滑管理 | 行情成为主内容，破坏性操作降级 |
| 详情页 ID、版本和状态挤在首屏 | 大标题与核心结论优先；“概览 / 证据 / 传导”分段；ID、版本放进资料详情 | 适合阅读，同时保留可追溯性 |
| 设置首页集中显示连接通道、Token、席位等技术项 | “我的”使用分组列表：账户、提醒、显示、数据；服务诊断与会话重置放入“高级设置” | 提高日常操作可理解性 |
| 研究页作为较深的独立入口 | 从事件详情和回答里的“保存到研究”衔接；研究项显示问题、状态、最近更新 | 保留从发现到跟踪的工作流 |

## 推演页优先细化

1. 问题原文保持可见，但用户气泡适度收窄；正文阅读区充分利用屏幕宽度。
2. 首屏先给一句结论，随后给有编号的两到四项解释。
3. 成立条件与待核验事项可展开，资料来源独立成行；不把原始 URL 堆在正文中。
4. 业务解释正确显示 background 模式，停止统一标作“官方证据链与图谱拓扑”。
5. 新问题建议使用简短、可直接验证的例子，不预设未发生的订单、二供或季度财务事实。
6. 当前后端采用同步 JSON 回答，等待状态显示“正在生成回答”和实际耗时；阶段进度只有接入真实服务端事件后才能展示。
7. 不把整段答案做打字动画；结果可直接阅读。用户已经上滑阅读时，新内容不强制抢走滚动位置。

## 动效规格

| 场景 | 建议 | 目的 |
| --- | --- | --- |
| 独立按钮按压 | 100–140ms，scale 0.98，松开恢复 | 即时确认触摸 |
| 列表行按压 | 80–120ms 的轻背景变化 | 保持文字清晰与位置稳定 |
| 分段选择 | 180–220ms，选中底板平移 | 保持选择的空间连续性 |
| 底部抽屉 | 约 260ms 打开、200ms 关闭，轻阻尼 | 呈现视图层级，支持自然返回 |
| 加入/删除自选 | 局部过渡、成功轻触觉；列表不整体重播入场 | 反馈动作结果 |
| 新回答 | 约 160ms 淡入、至多 4–6px 位移 | 减少内容突然出现的突兀感 |
| 首次加载 | 与最终布局相同的骨架占位，数据就绪再替换 | 避免跳动 |
| 行情刷新 | 数字替换与短暂颜色提示，不做滚动数字或整行飞入 | 优先保证快速读数 |

建议曲线：普通出现 `cubic-bezier(0.23,1,0.32,1)`；抽屉 `cubic-bezier(0.32,0.72,0,1)`。
高频输入、键盘操作和切换页面不加人为等待。CSS 只对明确属性设置 transition；替换当前自选页的 `transition: all`。

微信小程序采用 WXSS / 原生动画能力验证实现，不能直接假定浏览器的 blur、WAAPI 或现代 CSS 都支持。
磨砂不可用时有不透明背景回退。减少动态效果时去掉位移与弹跳，保留短淡入和必要的状态反馈。

## 实施顺序

1. 全局设计变量、导航、按钮、分组列表与推演正文组件。
2. 雷达、推演、自选三页；统一 loading、空态、错误、离线和重试表现。
3. 详情、研究、设置；统一抽屉与左滑交互。
4. 真机核对后再补深色模式与滚动标题收缩。

## 验收

- 在约 320、375、430px 可用宽度，以及 iOS/Android 真机上核对；长标题、长中文问题、大字体均不截断主要信息。
- 键盘弹出时输入框和发送操作可见；底部安全区、微信胶囊区域不被遮挡。
- 连续切换筛选、反向拖动抽屉、左滑后再纵向滚动时没有跳跃或误触。
- 首次加载、慢网、断网、会话失效和缺证据均有准确、可操作的反馈。
- 手势和动效不阻挡点击，不制造虚假的采集/模型进度或核验状态。
- 行情来自真实数据；没有历史序列时不画装饰性走势曲线。
- 发布客户端改版按小程序正常上传、审核和发布流程进行。
